Four ways the Skills LMS could look and feel.

Vivek's PR #1 already settled the plumbing — React 19, Tailwind v4, a single capability-gated shell, per-tenant accent theming, and a working People directory. What it deliberately doesn't decide is the look and the information architecture. Below are four complete directions. Each pairs a visual language with an IA bet and a persona it's built for. Every one shows the same hero screen — a learner's gap toward Data Engineer L2 — so you can compare looks directly, then a second screen that proves its structural idea.

01
Clearing
calm enterprise · gap-diff home

The restrained one. Slate neutrals, one indigo accent, hairline rules, room to breathe. The learner lands directly on their gap — no course wall to scroll. It reuses Vivek's shell almost verbatim, so it's the fastest path to a shipped Phase 1/2.

Left railWhitespaceIndigo accentReuses shell
Strengths
  • Lowest build cost — the AppShell & tokens already exist
  • Ages well; content carries the page, not chrome
  • Neutral base every persona tolerates
Tradeoffs
  • Least distinctive — needs disciplined spacing to not feel plain
  • Doesn't advance the "signature / trust" story
Best when

You want a demo in weeks and prefer to let Phase-2 features — not visuals — be the differentiator.

dense data-tool · heatmap-first

Built for the manager scanning a whole team. Compact rows, tabular numerals, a dark-capable surface, and a skill heatmap as the front door. Where 01 opens on one person's gap, Console opens on the shape of the team's capability — and lets you drill into any cell.

04
Path
guided roadmap · momentum

Turns the gap into a route. The learner's home is an ordered roadmap from where they are to their target grade, with the next step and its resource front-and-centre. Answers "what do I do next?" without a decision. The bet: this is what makes people come back.

Roadmap spineOrdered stepsResource-linkedTeal accent
Strengths
  • Highest learner adoption & return-visit pull
  • Makes “next action” unmissable — low cognitive load
  • Naturally showcases the resource catalogue
Tradeoffs
  • Needs a real roadmap/ordering engine on the backend (Phase 2)
  • Manager & admin analytics feel secondary here
Best when

The primary goal is changing individual learning behaviour, not reporting on it.

A point of view

What I'd recommend — but it's your call

You asked for options to choose from, so treat this as one vote, not a verdict. My read, given the Phase-1/Phase-2 timeline and that the shell already exists:

Recommendation

Ship 01 Clearing as the base, and borrow 02 Signet's verified-vs-self-declared idea as the one differentiator.

Clearing gets us a demo fastest because it reuses Vivek's shell and tokens almost untouched. Signet's “who verified this” treatment is the cheapest way to make the product feel like ours rather than a generic LMS — and it's exactly the repo's stated thesis. Console's heatmap is the right manager view regardless of which direction wins, so plan for it in Phase 2. Path is the most exciting learner bet, but it depends on a roadmap engine that doesn't exist yet — a strong Phase-2/3 candidate once the core loop runs.

IF 01 / 02
Design tokens + one hero screen built for real this week; slots straight into the existing AppShell.
IF 03
Start with the heatmap data contract — the readiness/gap API shape drives everything.
IF 04
Scope the roadmap/ordering engine first; the UI is easy once step-ordering exists.
